Cortex · self-improving skills for Claude Code

Skills that earn their place.

Cortex turns your everyday coding into a loop that writes new skills, measures whether they actually help, and deletes the ones that don't — using nothing but your own past work as the test. And it keeps each one loaded only where it matters, so your context stays lean.

Collect what keeps going wrong  →  measure one fix against the real jobs  →  remove whatever stopped pulling its weight.

/prune Delete what stopped earning its place monthly · & after every model upgrade

Every always-on skill sits in Claude's context on every turn, forever. Prune measures what removing a skill or rule would really cost — on a throwaway copy, never touching your live ones — and deletes only what costs nothing. It also narrows: a skill used in one area only moves to a path-gated skill or rule that loads only when Claude touches that area. A new model may already know what an old skill teaches. Nothing runs until you approve the plan — it shows the rollouts, time, tokens and cost first.

the thinking behind it

Three simple ideas

The overview showed the workflow. These are the ideas that make it trustworthy — each one is something you already understand from everyday life.

1

A test is a bug you can replay

Like a checkpoint in a video game. When you fix something, Cortex saves the "before" — so it can drop any skill back into that exact broken moment and see if it copes, as many times as it likes.

why it matters These saved checkpoints become the ruler everything else measures against. No ruler, no way to tell a good skill from a bad one — which is why collecting comes first.
Why the tests rewind to the broken commit, while the skills stay at today →
2

Judge a skill like a fair taste test

Two identical plates. One has the new spice, one doesn't — everything else is the same. If the spiced plate wins, it was the spice. That's exactly how a new skill is judged: the same jobs, run with it and without it, side by side.

the one rule that matters A skill is kept only if it helps at least one job and makes none of the already-working jobs worse. Not "better on average" — nothing you rely on is allowed to break. That single rule is why your skill set never quietly rots.
3

Keep only what would be missed

Take an ingredient out of the recipe. If the dish tastes exactly the same, it wasn't doing anything — so drop it. Skills get the same treatment, because every always-on one you keep costs the agent a little attention on every single task.

never used ≠ useless A skill the agent never reaches for during the tests is not deleted: the tests simply can't see it, so it stays and is marked unmeasured. How long ago a skill was last used never decides a deletion — it only helps choose what is worth testing.

It's a loop, not a line

Harvest feeds evolve, evolve feeds prune, and the whole thing keeps turning — every week your agent gets a little sharper, and never heavier.

What ties it together

Each command is a fresh session with no memory of the last. These files on disk are the memory — written by one command, read by the next.

.evolve/tasks/
The ruler. Real bugs, replayable forever. Grown by harvest, used by evolve & prune.
lessons.md
One line per correction. Written by harvest, mined by evolve to find what recurs.
journal.md
Every verdict, kept or killed. So next week's evolve never retries a dead idea.
.evolve/runs/
One results file per sweep: every rollout's pass or fail, what loaded, and its tokens, cost and time. Read by cortex score, and by the next plan's estimate.
prune-plan.json
The prune pass you approved: which items, on which tasks, the estimate, and what was decided — so a pass resumes across turns.
.claude/skills/ & rules/
The live set, in tiers: always-on skills, path-gated skills and rules that load only when Claude touches their paths. Grown by evolve, trimmed and narrowed by prune, checked by cortex skills.

Nothing here changes the model. Cortex evolves only the harness around it — and every gain is a diff you can read.  ·  cortex init to begin.
